# ครัวขนม — ระบบต้นทุนและสต็อกร้านขนม

แอปสำหรับร้านขนมขนาดเล็ก **พิมพ์บอกแบบที่พูด** แล้วระบบจดให้ คิดต้นทุนให้
บอกว่าควรตั้งราคาขายเท่าไหร่ และสรุปกำไร-ขาดทุนให้ดูทุกวัน

ใช้งานผ่านมือถือได้เต็มจอ ข้อมูลเก็บอยู่ในเครื่องผู้ใช้ (localStorage) ไม่ต้องมีเซิร์ฟเวอร์

---

## ทำอะไรได้บ้าง

### 1. จดของที่ซื้อผ่านช่องแชท พร้อมคิดต้นทุนต่อหน่วยให้เอง

```
ซื้อกล่อง p39 1 ลัง ลังละ 1000 กล่อง ราคารวม 1680 บาท
```
→ บันทึกลง **บรรจุภัณฑ์** · 1,000 กล่อง · **1.68 บาท/กล่อง**

```
ซื้อมะม่วง 3 กิโล ราคารวม 112 บาท
```
→ บันทึกลง **ของสด** · 3,000 กรัม · **37.33 บาท/กก. (0.0373 บาท/ก.)**

จัดหมวดหมู่ให้อัตโนมัติ (ของสด / ของแห้ง / บรรจุภัณฑ์ / อื่นๆ) และคิดต้นทุน
แบบถัวเฉลี่ยเคลื่อนที่เมื่อซื้อของเดิมซ้ำคนละราคา

### 2. สูตรเมนู ที่ดึงสต็อกจริงมาคิด

```
สูตรเค้กมะม่วง ได้ 20 กล่อง ใช้ มะม่วง 1500 กรัม, แป้งเค้ก 800 กรัม, กล่อง p39 20 กล่อง
ทำเค้กมะม่วง 20 กล่อง
```
ระบบตัดสต็อกวัตถุดิบและบรรจุภัณฑ์ให้ครบ แล้วบอกว่าใช้ไปเท่าไหร่ เหลือเท่าไหร่

### 3. ต้นทุนต่อกล่อง รวมค่าแรง ค่าน้ำ ค่าไฟ ค่าจิปาถะ

ตั้งค่าใช้จ่ายเหล่านี้ต่อ 1 รอบผลิตในหน้าเมนู ระบบเฉลี่ยลงต่อกล่องให้
พร้อมแถบแสดงสัดส่วนว่าต้นทุนไปอยู่ตรงไหนมากที่สุด

### 4. เครื่องคิดราคาขาย

เลือกกำไรที่ต้องการ (20% / 30% / 40% / 50% / 60% หรือใส่เอง) แล้วระบบบอกว่าควรขายกี่บาท
เลือกได้ว่าจะตีความเปอร์เซ็นต์แบบ **บวกจากทุน** หรือ **คิดเป็นสัดส่วนของราคาขาย**
และสั่งปัดราคาขึ้นเป็นหลัก 1 / 5 / 10 บาทได้ หรือจะกำหนดราคาเองแล้วดูว่าได้กำไรกี่ % ก็ได้

```
ต้นทุนเค้กมะม่วง กำไร 40%
```

### 5. รายงานและแดชบอร์ด

ยอดขาย · กำไรสุทธิ · กำไรจากการขาย · กราฟยอดขายเทียบต้นทุนรายวัน ·
อันดับเมนูที่ทำเงินได้ดีที่สุด · มูลค่าของที่ยังขายไม่ออก · ของเสีย · วัตถุดิบใกล้หมด

### 6. ของเหลือจากเมื่อวาน ที่ยังขายได้

```
เหลือเค้กมะม่วง 5 กล่อง
```
ระบบเตรียมไว้ขายวันถัดไปโดย **ไม่คิดต้นทุนซ้ำ** เพราะคิดไปแล้วตอนผลิต
เมื่อขายได้จึงเป็นกำไรเต็มจำนวน — ถ้าพิมพ์บอกในวันถัดมาเกี่ยวกับของที่ค้างจากเมื่อวาน
ระบบจะให้พร้อมขายวันนี้เลย

ถ้าขายไม่ได้แล้ว สั่ง `ทิ้งเค้กมะม่วง 2 กล่อง เพราะบูด` เพื่อบันทึกเป็นความเสียหาย

## คำสั่งในแชททั้งหมด

| ต้องการ | พิมพ์ว่า |
| --- | --- |
| ซื้อของ | `ซื้อมะม่วง 3 กิโล ราคารวม 112 บาท` |
| ซื้อยกลัง | `ซื้อกล่อง p39 1 ลัง ลังละ 1000 กล่อง ราคารวม 1680 บาท` |
| ราคาต่อหน่วย | `ซื้อนมสด 2 ขวด ขวดละ 25` |
| ตั้งสูตร | `สูตรเค้กมะม่วง ได้ 20 กล่อง ใช้ มะม่วง 1500 กรัม, กล่อง p39 20 กล่อง` |
| ทำขนม | `ทำเค้กมะม่วง 20 กล่อง` |
| ขาย | `ขายเค้กมะม่วง 15 กล่อง กล่องละ 120` |
| ของเหลือ | `เหลือเค้กมะม่วง 5 กล่อง` |
| ของเสีย | `ทิ้งเค้กมะม่วง 2 กล่อง เพราะบูด` |
| ถามต้นทุน | `ต้นทุนเค้กมะม่วง กำไร 40%` |
| ถามสต็อก | `สต็อกมะม่วง` |
| นับสต็อกใหม่ | `ปรับสต็อกมะม่วง 800 กรัม` |

พิมพ์หลายบรรทัดพร้อมกันได้ บรรทัดถัดไปจะถือว่าเป็นคำสั่งเดียวกับบรรทัดแรก:

```
ซื้อมะม่วง 3 กิโล 112 บาท
แป้งเค้ก 1 กก. 45 บาท
เนยสด 500 กรัม 120 บาท
```

รองรับเลขไทย (`๕ กก.`) คอมมาคั่นหลักพัน (`1,680`) และหน่วยไทยกว่า 60 หน่วย
(กรัม ขีด กิโล ปอนด์ มล. ลิตร ช้อนโต๊ะ ถ้วยตวง กล่อง ใบ ฟอง แผง ลัง โหล ฯลฯ)

## วิธีคิดกำไรของแอปนี้

แอปแสดงกำไรสองมุม เพราะสองอย่างนี้ตอบคนละคำถาม

- **กำไรจากการขาย** = ยอดขาย − ต้นทุนของขนมที่ขายไปจริง
  ใช้ดูว่าราคาที่ตั้งไว้ดีพอไหม
- **กำไรสุทธิ** = ยอดขาย − ต้นทุนที่ลงมือผลิตในช่วงนั้น
  ใช้ดูว่าวันนั้นทำแล้วคุ้มไหม ถ้าทำเยอะแล้วขายไม่หมด ตัวเลขนี้จะลดลงเอง

ต้นทุนถูกรับรู้ในวันที่ผลิต ของที่ยกไปขายวันถัดไปจึงไม่ถูกคิดทุนซ้ำ

## เชื่อมกับระบบบัญชีรายรับ-รายจ่ายที่ใช้อยู่

ไปที่ **ตั้งค่า → ส่งออกไปลงบัญชีรายรับ-รายจ่าย** เลือกช่วงวันที่ แล้วดาวน์โหลดเป็น CSV หรือ JSON

ยอดขายจะกลายเป็น **รายรับ** และค่าซื้อของกลายเป็น **รายจ่าย** แยกตามหมวด
(ซื้อของสด / ซื้อของแห้ง / ซื้อบรรจุภัณฑ์ / ซื้ออื่นๆ) ในรูปแบบกลางที่ระบบไหนก็นำเข้าได้

| คอลัมน์ | ความหมาย |
| --- | --- |
| `วันที่` | รูปแบบ YYYY-MM-DD |
| `ประเภท` | `รายรับ` หรือ `รายจ่าย` |
| `หมวดหมู่` | เช่น ขายขนม, ซื้อของสด, ซื้อบรรจุภัณฑ์ |
| `รายการ` | ชื่อเมนูหรือชื่อของที่ซื้อ |
| `จำนวนเงิน` | เป็นบวกเสมอ ใช้คอลัมน์ประเภทบอกทิศทางแทน |
| `หมายเหตุ` | รายละเอียดเพิ่มเติม |

ไฟล์ CSV มี BOM นำหน้าและใช้ CRLF จึงเปิดใน Excel ภาษาไทยได้โดยไม่เป็นตัวยึกยือ
ส่วนไฟล์ JSON ใช้ schema `bakery-ledger/v1` มีช่วงวันที่และยอดรวมกำกับ เหมาะกับการเขียนตัวนำเข้าอัตโนมัติ

**ค่าแรง ค่าน้ำ ค่าไฟ ค่าจิปาถะ ไม่ถูกรวมมาโดยปกติ** เพราะเป็นค่าประมาณที่ตั้งไว้ในสูตร
ขณะที่บิลจริงมักถูกบันทึกในระบบบัญชีอยู่แล้ว รวมมาด้วยจะกลายเป็นบันทึกซ้ำสองที่ — ติ๊กเปิดได้ถ้าต้องการ

### ทำไมต้องผ่านไฟล์

แอปนี้กับระบบบัญชีของคุณอยู่คนละโดเมน และเบราว์เซอร์แยกพื้นที่เก็บข้อมูล
(localStorage / AsyncStorage) ตามโดเมนอย่างเด็ดขาด แอปหนึ่งจึงอ่านข้อมูลของอีกแอปโดยตรงไม่ได้
ถ้าต้องการให้ข้อมูลไหลอัตโนมัติแบบไม่ต้องส่งไฟล์ ต้องมีฐานข้อมูลกลาง (เช่น Supabase, Firebase)
ที่ทั้งสองระบบเชื่อมเข้าหา ซึ่งต้องแก้ทั้งสองฝั่ง

## รันโปรเจกต์

```bash
npm install
npm run dev      # เปิดที่ http://localhost:5173
npm test         # เทสต์ตัวแปลภาษาไทย สูตรคำนวณ และการส่งออกบัญชี (62 เคส)
npm run build    # สร้างไฟล์สำหรับขึ้นเว็บใน dist/
```

ถ้าจะขึ้น GitHub Pages ใต้ path ย่อย:

```bash
BASE_PATH=/jompol-bourchoom/ npm run build
```

## โครงสร้างโค้ด

```
src/
  types.ts              โครงข้อมูลทั้งหมด
  lib/
    units.ts            หน่วยไทย -> หน่วยฐาน (กรัม / มล. / ชิ้น)
    parser.ts           แปลข้อความไทยเป็นคำสั่ง  (ฟังก์ชันบริสุทธิ์ เทสต์ได้)
    engine.ts           ลงมือแก้ข้อมูลตามคำสั่ง + ข้อความตอบกลับ
    calc.ts             ต้นทุน ราคาขาย และตัวเลขสรุป
    store.tsx           state กลาง + เก็บลง localStorage + ปุ่มย้อนกลับ
    format.ts           จัดรูปแบบตัวเลข เงิน วันที่ ภาษาไทย
    ledger.ts           แปลงยอดขาย/ยอดซื้อ เป็นรายการรายรับ-รายจ่าย (CSV / JSON)
  components/           ชิ้นส่วน UI และกราฟ SVG (ไม่ใช้ไลบรารีกราฟภายนอก)
  pages/                แชท · สต็อก · เมนู · ขาย · สรุป · ตั้งค่า
docs/palette.md         ชุดสีกราฟและผลตรวจ contrast / ตาบอดสี
```

## ข้อมูลของคุณอยู่ที่ไหน

เก็บอยู่ในเบราว์เซอร์ของเครื่องที่ใช้เท่านั้น ไม่ได้ส่งออกไปที่ไหน
หน้า **ตั้งค่า → สำรองข้อมูล** ดาวน์โหลดไฟล์สำรองเก็บไว้ และนำเข้ากลับได้เมื่อเปลี่ยนเครื่อง
